# 玄灵界终端前端原型设计

日期：2026-06-15
范围：仅前端高保真原型，不新增、不修改后端接口与服务端逻辑。

## 目标

制作一个面向 LLM 动态推演游戏的复杂 Web 前端框架。界面服务于群像修仙文字 RPG / 玄幻战略生存玩法，背景为“玄灵界·元极天”。成品应是可运行、可点击、可展示多界面与多模态框的前端原型，而不是后台管理式页面。

## 设计方向

采用“沉浸式玄灵界终端”结构：固定全局导航、中央高信息密度内容区、可弹出的角色/据点/技能/背包/通知详情层。整体视觉为深渊暗黑修仙与古风鎏金结合：幽黑、墨蓝、暗红为底，暗金、翠玉、血红作为功能强调色。

禁止使用 emoji。所有导航、地图节点、角色印记、警示图形使用统一风格的 inline SVG 图标。

## 页面架构

主界面包含六个可切换功能区：

1. 轮回者状态
   展示陆星遥、李明远、叶汐澜、楚凌霜四名主角卡片。每张卡包含姓名、前世宿命、当前境界、所在地、状态、六维属性条。危险角色以血色边框、脉冲警戒线、状态角标体现。

2. 玄灵双轨舆图
   提供宏观“大千界域图”和微观“现世战略图”切换。宏观图展示大日、大赤天、太初天、元极天、黑海侵蚀区等节点，以星轨/阵法线连接。微观图展示荒骨城、黑海裂隙、太虚剑碑、血影沼泽、太古神山等地点。地点图标使用阵纹、城池、裂隙、遗迹等 SVG。四名角色使用专属令牌显示在不同地点。

3. 天机缘法
   技能树原型，展示主角团共用/个人修行路线。节点可点击打开技能详情模态框，内容包括品阶、归属、修行进度、风险和推演建议。

4. 须弥纳戒
   背包原型，展示法宝、丹药、残卷、材料。空态文案必须符合世界观，如“空间法则已被污染，须弥纳戒被禁制锁死”。物品卡可点击打开详情。

5. 因果卷宗
   展示轮回记录、关键事件、NPC 关系、黑海侵蚀情报。采用卷宗式排版，支持标签页切换。

6. 天道设置
   纯前端设置面板原型，展示 LLM 交互相关配置入口、演出开关、文本密度、动画强度等，不接入真实后端。

## 交互设计

所有核心元素均可点击，并使用内部模态框、右侧抽屉或 Toast 展示反馈：

- 点击角色卡：打开角色详情抽屉，展示前世、当前危机、属性明细、所在地点、近期因果。
- 点击地图节点：打开据点详情模态框，展示所属界域、威胁等级、驻留角色、可推演行动。
- 切换地图层级：使用分段控制器在宏观/微观图之间切换，动画保持空间连续感。
- 点击技能节点：打开技能详情模态框。
- 点击背包物品：打开物品详情模态框。
- 点击危险提示：触发内部 Toast 与通知面板，不使用浏览器 alert 或 confirm。

所有交互元素必须有唯一、描述性的 id，便于浏览器测试。

## 视觉系统

字体优先使用 Noto Serif SC，并设置现代排版尺度、行高与字重。界面不依赖浏览器默认字体。

背景由多层组成：深渊基底、黑海鳞纹、暗红天幕、星火微粒、低透明雾层。主要面板使用伪鎏金边框、紫金流光、血色警戒线和多层阴影，避免扁平后台感。

动画原则：微交互使用 transform 和 opacity，避免布局抖动。按钮 hover 有光泽扫过，卡片 hover 有轻微浮起与边框亮起，危险状态有低频血色呼吸。支持 prefers-reduced-motion。

## 技术约束

- 仅修改前端 React/CSS 相关文件。
- 不新增后端路由、数据库或 API。
- 使用语义化 HTML5：nav、main、section、article、header、aside、dialog 等。
- 禁止 emoji。
- 保持项目现有 React/Vite 架构。
- 尽量避免新依赖；优先 inline SVG 和 CSS 动画。
- 完成后运行测试和构建。
- 修改完成后提交并推送到 GitHub 仓库。

## 验收标准

- 首屏具有强烈 Dark Fantasy Xianxia 氛围，不像普通后台系统。
- 左侧导航、四主角卡、双轨地图、技能树、背包、卷宗、设置均可见且可交互。
- 地图节点不是普通圆点，而是具备主题的 SVG 图标。
- 四名主角令牌出现在地图对应位置。
- 所有点击行为使用内部模态框、抽屉或 Toast。
- 无 emoji。
- 测试和构建通过。
